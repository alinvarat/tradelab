# Instructions for AI agents working in this repo (Claude, Codex, Gemini, DeepSeek-based tools, others)
Two people work here, each with their own AI. Follow this file and `CONTRIBUTING.md`; if a user instruction conflicts, say so and ask.
1. **Scope:** simulated money and public data only. Never place real orders, create broker/exchange accounts, use trading keys, insider data or manipulation. **Never read, print, paste, store or commit an API key or password** (the OpenRouter key is a Kuber secret that only the owner sets; a key pasted in chat is compromised and must be revoked).
2. **Read first:** `ops/RUNBOOK.md` (daily procedure, definition of done, incident steps), `ops/SYSTEM_MAP.md` (what runs where, state, how to check), `reports/STATUS.md` (current state and work queue), `ROADMAP.md` (plan, change checklist), `HANDOFF_3X_PROMPT.md` (history and state), `research/LESSONS.md` (closed research, mistakes), the protocol file of the experiment you touch. Do not redo closed experiments.
3. **Do not run the project on the owner's computer.** No local servers, scratch instances, live-data dry runs, LLM calls, systemd services or timers. Write code, push a branch, open a PR; GitHub Actions runs the unit tests (`python -m unittest discover -s tests -t .`); verify behaviour on the Kuber deployment (https://tradelab.dgnr.us) with read-only requests. Static checks (syntax parse) and reading code are fine.
4. **Workflow:** `git pull --rebase origin main`, check open PRs/issues so you do not duplicate the other person's AI, work on a branch, add offline tests for every new calculation, merge when CI is green. A merge to `main` that touches app files **deploys to production** and restarts the pod (state is on the volume); deploys have failed on the platform side before: re-run the failed job, do not "fix" the code for a platform error.
5. **Locked protocols** (`research/*/protocol.md`, the DVOL `protocol.md` is hash-locked by a test): do not edit rules, thresholds, windows or criteria to get a better result; write a new dated protocol or an addendum before the first affected data, and say so in the PR.
6. **Research honesty:** fix the rule, window, size, costs and the control before opening confirmation data; use new non-overlapping periods; compare with a random control under the same costs; report ending equity, worst drawdown and the result at higher cost; report "not found" when that is the result. Never claim a result you did not compute and read. A one-off gain, top-ups or a depleted account do not count as reaching a target.
7. **Models (owner 2026-11-25): Claude only.** Every LLM call in TradeLab (bot roles, headline scoring, research studies, forward tests) goes through `core.ai_news.chat` to Claude Haiku 5.5 (`claude-haiku-5-5`) via the Claude Code CLI on the owner's Claude Max plan: secret `CLAUDE_CODE_OAUTH_TOKEN` (made by the owner with `claude setup-token`) on Actions and Kuber, or `TRADELAB_CLAUDE_AUTH=cli` on a machine whose Claude Code is logged in. Without Claude, calls return empty with a clear reason; DeepSeek/OpenRouter/free models run only if `TRADELAB_OTHER_MODELS=1` is set explicitly (do not set it). A locked protocol that names another model needs a dated Claude addendum before new data; never pool results across models; no aliases.
8. **Record:** lessons in `research/LESSONS.md` (English), state in `HANDOFF_3X_PROMPT.md` (Thai), decisions in issues/PRs so the other person's AI can read them. Keep docs consistent with the code in the same PR (a contradiction between a doc and the code is a bug).
9. **Never commit:** live account files (`data/*.json`), `data/backups/`, news/buzz/dvol data, secrets, personal details. Use your human's GitHub identity or `tradelab-research` with the noreply email.
