# L4 Polymarket: ตั้งราคาขายฝั่งที่โอกาสต่ำ (maker longshot)

**สมมติฐาน:** ตัวเลือกที่ราคาต่ำกว่า 10¢ มีราคาสูงกว่าโอกาสจริง (favourite-longshot bias) การวางคำสั่งขายแบบ maker (ค่าธรรมเนียม 0) จึงมีผลตอบแทนคาดหวังเป็นบวก
**ต่างจากงานที่ปิดแล้ว:** งาน `polymarket_llm` ที่ไม่พบ edge ใช้ LLM ทายผล ส่วนเส้นนี้ไม่ใช้ LLM และใช้โครงสร้างราคาเท่านั้น
**หลักฐานเบื้องต้น:** บันทึกค้นคว้า event_prediction.md (ในเครื่องเจ้าของ ไม่อยู่ใน repo) ข้อ 7 (H2) ระบุว่าทิศทางนี้มีงานวิจัยจาก 588 ล้านเทรดรองรับ แต่ผลต่อไม้เล็ก

## ข้อมูล (ตรวจแล้ว 24 พ.ย. 2026)
- **รายการตลาดที่จบแล้ว:** `https://gamma-api.polymarket.com/markets?closed=true&limit=500&offset=<n>` ใช้ฟิลด์ `clobTokenIds`, `outcomePrices`, `endDate` และ `volumeNum`
- **ราคาประวัติ:** `https://clob.polymarket.com/prices-history?market=<clobTokenId>&interval=max&fidelity=60`
  - **ระวัง:** ต้องใส่ token id ไม่ใช่ `conditionId` ถ้าใส่ `conditionId` จะได้ `history: []` กลับมา

## ด่านคัดกรอง
- **event:** ตัวเลือกที่ราคาอยู่ระหว่าง 2¢ ถึง 10¢ ที่ T−7 วัน, T−3 วัน และ T−1 วันก่อน `endDate` โดยตลาดต้องมี `volumeNum` มากกว่า $50k
- **ผลต่อหน่วย:** ขายที่ราคา p ได้ +p ถ้าตัวเลือกนั้นไม่เกิด และ −(1−p) ถ้าเกิด (ไม่มีค่าธรรมเนียม maker)
- **สมมติฐานการ fill:** ถือว่า fill เฉพาะเมื่อราคาแตะระดับเดียวกันอีกครั้งภายใน 24 ชม.
- **ผลต่อเดือน:** หารด้วยเงินที่ถูกล็อก (1−p) และจำนวนวันที่ถือ
- **แบ่งข้อมูลตาม `endDate`:** ก่อน 2025-07 = train, 2025-07 ถึง 2026-03 = validation, หลังจากนั้น = test
- **cluster:** ใช้ event เดียวกัน (ตลาดหลายตัวเลือกของ event เดียว) ใน bootstrap

- **ผ่าน:** validation ได้ผลมากกว่า 0 โดย p < 0.05 และผลต่อเงินที่ล็อกต่อเดือนมากกว่า 5%
- **ตัด:** ไม่เข้าเกณฑ์ผ่าน

**ความเสี่ยงที่ต้องรายงาน:** ขาดทุนต่อไม้สูงสุดคือ 1−p (เกือบ 100% ของเงินที่วาง) ให้รายงาน drawdown ที่แย่ที่สุดของ validation ด้วย
