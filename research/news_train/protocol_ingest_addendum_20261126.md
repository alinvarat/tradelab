# News train: pod ingest log as a forward data source, addendum 2026-11-26 (rounds 2 and 3; written before the first forward item, 2026-11-27 00:00 UTC)

Locked files are not edited: `protocol_r2_20261126.md` and its addenda, `protocol_r3_20261126.md` and its addenda, the `params*.json`, `LOCK*.json`, `versions*.json`, the prompts and `logic*.py`. This file only adds a data source and two descriptive outputs. The round-2 protocol said the pod's `/api/news_latency` ingest log "is behind Cloudflare and not reachable from Actions"; from this date the pod can publish it (`core/news_publish.py`) to the append-only branch `data/news-ingest` (`news_ingest/<YYYYMMDD>/<start>-<end>.jsonl`, rows `item` and `llm` with `source`, `key`, `t_pub`, `t_seen`, `t_llm`). The branch stays empty until the owner sets the secret `TRADELAB_DATA_PUSH_TOKEN`; nothing below depends on it.

**Round 2, forward stock set (unchanged).** Item discovery stays EDGAR-built, the universe, text, redaction, the 93 s proxy entry, costs, the locked stock version, the trigger (`fwd_trigger`), the Holm family and the one-shot `result.json` are exactly as locked. The ingest log is read only after the forward step has written its items, and only to write `fwd/ingest_timing.json` on `data/news-train-r2`: for every forward item the pod's row `sec_8k` / `sec:<accession>` is joined (rows de-duplicated on event, source and key), giving `t_seen`, `t_llm`, `seen_minus_pub_s` and `seen_minus_proxy_s` (seen minus published minus 93 s), plus a coverage count (items with a pod row, missing, median seen-minus-published). An item with no pod row is listed as missing; it is never dropped, imputed or re-timed. The pod's own Haiku reading (`parsed`) is never used: it comes from a different prompt and is not a round-2 decision. Entry, decisions, calibration and scoring never read this file; a later entry rule based on `t_seen` needs its own dated protocol before any outcome is read.

**Round 3, forward arm (source registration only).** Round 3 has no registered forward rule: Track A is sealed-historical (it refuses items at or after the round-2 forward start) and Track B2 is sealed-historical GKG. This addendum registers no threshold, version, hold, cost or test. It registers one data source for any later forward round-3 protocol: wire press releases `prnewswire`, `globenewswire`, `businesswire` in the ingest log. The scheduled job (`news_train_r3.yml` mode `fwd_ingest`, cron 50 22 * * 1-5) writes counts only (`fwd_ingest/progress.json` on `data/news-train-r3`: rows, rows with an LLM timing, median seen-minus-published per wire). It resolves no tickers, snapshots no bars and reads no outcome. Scoring these items requires a new dated round-3 protocol (rule, window, size, costs, random control) written before the first outcome is read.

**Not changed:** the round-1/2/3 locks, the sealed one-shot runs, the models (Claude Haiku 5.5 only), costs, and the rule that the log is measured, not fed to the trader. Stated limits: pod rows exist only from the day the owner enables publishing, so earlier forward items have no timing; the log's `t_pub` for `eqn_*` is the newswire relay time; wire items have no ticker in the log.
